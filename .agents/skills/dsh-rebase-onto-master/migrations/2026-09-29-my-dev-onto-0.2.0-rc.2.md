Adds the local-requirement-note workflow: a trailing `## Local requirement notes` rule in root `AGENTS.md`, the `dsh-rebase-onto-master` skill that writes one note per local requirement or fix under `.agents/skills/dsh-rebase-onto-master/notes/`, the note and migration READMEs, and the migration documents for the earlier bases. Paths: `.agents/skills/dsh-rebase-onto-master/`, `AGENTS.md`. Machine-facing: none.

### fix(open-in-app): Windows 定位器改用 --new-window 并过滤继承的 Electron Node 模式

On Windows, `packages/host/open-in-app` passes `--new-window` from the VS Code locators, so opening a second workspace focuses a window already holding that exact directory instead of loading the new directory into the last active window and evicting the project it held. The behaviour no longer depends on the deployment-invisible `window.openFoldersInNewWindow` setting.

`launchDetachedApp` also drops the inherited `ELECTRON_RUN_AS_NODE` before merging the adapter's explicit `launch.env`. The Desktop Host runs the shared Web application through the same Electron executable in Node mode, and `scrubbedParentEnv()` preserved that selector, so every GUI application the header button launched started as Node, rejected its own argv, exited nonzero inside the launch watch window, and was reported as a failed launch. An adapter that deliberately needs Node mode — GitHub Desktop's packaged CLI — still declares it and receives it.

Paths: `packages/host/open-in-app/src/catalog.ts`, `src/resolver.ts`, `tests/resolver.spec.ts`. Machine-facing: none.

### fix(fs-local): 重试 ReplaceFileW 瞬时共享锁与 1175 删除冲突

`packages/fs/fs-local` retries `ReplaceFileW` on Win32 errors 32, 33, and 1175 after 25, 50, and 100 ms, maps exhaustion to `EBUSY`, lets the write abort signal cancel a retry wait, and keeps publication on `ReplaceFileW` instead of falling back to rename.

Paths: `packages/fs/fs-local/src/win32.ts`, `src/fsio.ts`, `tests/win32.spec.ts`, `tests/fsio.spec.ts`. Machine-facing: none.

### feat(web): 图标改为圆角光栅图标集并拆分 maskable 用途

The browser tab and installed application switch from `favicon.svg` to a raster set. `favicon.ico`, `icon-192.png`, and `icon-512.png` are rounded with alpha; `icon-maskable-192.png`, `icon-maskable-512.png`, and `apple-touch-icon.png` stay opaque so the platform mask does not cut a second shape. The manifest declares real pixel sizes and splits `purpose` into `any` and `maskable`. `packages/host/frontend-static` gains `.png` and `.ico` MIME entries without which the icons serve as `application/octet-stream`, and the desktop bundle allowlist in `apps/desktop/src/main.ts` grows from `/favicon.svg` to the raster paths so the packaged app does not 404 its own icons.

Paths: `apps/web/public/*`, `apps/web/index.html`, `apps/web/tests/pwa-manifest.e2e.ts`, `apps/web/tests/clickable-links-gallery.e2e.ts`, `apps/web/tests/settings-chrome.e2e.ts`, `apps/desktop/src/main.ts`, `packages/host/frontend-static/src/index.ts`, `packages/host/frontend-static/tests/frontend-static.spec.ts`. Machine-facing: every `apps/web/public` file is served from a fixed URL.

### chore(scripts): 新增 DSH Web 启动脚本与开始菜单快捷方式安装脚本

Adds `dsh-web.ps1` (runs `pnpm dsh web --no-open` from the repository root and propagates pnpm's exit code) and `install-dsh-web-shortcut.ps1` (creates the `DSH Web` Start Menu shortcut, renders a multi-size icon with ImageMagick, and refreshes an existing taskbar pin).

Machine-facing: both scripts are new. `dsh-web.ps1` requires `pnpm` and `pwsh` on `PATH`; the installer also looks for `magick`, which is optional.

### feat(ui-workspace): 折叠的工作区分组图标增加执行中与已完成未读提示

The sidebar session tree's Workspace (folder) header reports both hidden row states while the group is folded. A folded group shows no session rows, so their status dots are off screen; the header's closed-folder glyph carries the same animated `ongoing` state dot as a badge, labelled `group.running` (`有会话正在运行` / `A session is running`), and the `done` reminder of a member that finished running while not selected and not yet viewed, labelled `group.completed` (`有会话已完成，未读` / `A session finished and is unread`). Running takes the badge seat when both are true, so the two states never stack.

`GroupNode.running` is derived in `deriveGroups` from the group's visible members, counting direct children through each Session's subagent catalog. `GroupNode.completedUnread` is derived from those members' `completionUnread` status, and subagent-origin rows are never visible members. Both are always false while the group is expanded, where each row carries its own status dot. The badges take no focus; the enclosing row keeps its single toggle action.

Paths: `packages/client/ui-workspace/src/client/tree.ts`, `rows/Rows.tsx`, `rows/Rows.module.css`, `locales.ts`, `tests/tree.client.spec.ts`, `tests/rows.client.spec.tsx`. Machine-facing: none.

### fix(desktop-host): 修复 Windows 打包版 LibreOffice 引擎路径过长

Packaged Windows LibreOffice conversion fails when the unpacked engine directory is long enough that LibreOffice's `file:///` resource URLs exceed 260 characters: the resources are addressed from the program directory, and the deepest registry resource crosses the Windows 260-character limit with `stat'ed file did not exist`.

The fix replaces module hooks, which only reached the Electron Host thread, with a short junction: the Desktop Host publishes `%LOCALAPPDATA%\dsh-libreoffice-kit\node_modules` and writes a `libreoffice-cli.mjs` entry beside it that starts the CLI with `--preserve-symlinks` and `--preserve-symlinks-main`, so a child `node.exe` — the path the Office skill tells the model to run — stays on the alias instead of `realpath`ing back to the long directory. Aliases are skipped when the engine directory already fits, and a location that is itself over the limit fails loud instead of silently falling back.

Paths: `apps/desktop-host/src/office-engine.ts`, `apps/desktop-host/src/office.ts`, `apps/desktop-host/tests/office-engine.spec.ts`. Machine-facing: none.

### feat(desktop): 新增渲染进程唤起窗口的 IPC 通道

A notification click switches the Session, but the renderer cannot raise its own window: Chromium requires a browser-layer implementation that Electron does not expose, so the switched Session would render behind whichever application is in front. The Desktop application gains the `window.reveal()` product API, backed by the `dsh-desktop:window-reveal` channel. The preload exposes `reveal()` on `window`, and the main process handles it by calling `focusPrimaryWindow` after `assertProductSender` checks the caller's document origin, restoring, showing, and focusing the existing window. No window is created when none is open.

Paths: `apps/desktop/src/ipc.ts`, `src/main.ts`, `src/preload-app.ts`, `tests/main-startup.spec.ts`, `tests/preload-app.spec.ts`. Machine-facing: a new IPC channel name a packaged renderer invokes, and a new member of the preload-exposed product API.

### feat(desktop): 应用与托盘图标改用 Web 启动器同款圆角原稿

The Desktop application, installer, and uninstaller icons were whale/gradient artwork unrelated to the Web launcher icons, so one product showed two marks. `apps/desktop/resources/icon.png` now holds the same square artwork the Web application ships, and `pnpm run render:icons` derives every Desktop artifact from it at the Web corner radius (22% of the edge): full-bleed `icon-windows.png`, transparent-margin `icon-macos.png`, and the 16–64 px `tray-windows.ico` bitmaps. The whale vectors `icon.svg`, `icon-windows.svg`, and `icon-macos.svg` are deleted, and the `render:tray-icon` script is renamed to `render:icons`.

Paths: `apps/desktop/resources/*`, `apps/desktop/scripts/render-app-icons.ts`, `apps/desktop/scripts/render-tray-icon.ts`, `apps/desktop/tests/tray-icon.spec.ts`, `apps/desktop/package.json`. Machine-facing: the renamed script, and the icon files the installer and the tray read.

## Compatibility with this machine

Rows marked **branch** come from this branch. Rows marked **profile** are state a checkout keeps outside the repository that `git pull` cannot migrate. Host paths, host versions, and local state are deliberately not recorded here; the requirements below are what another machine must satisfy.

| Item | Required by | Result |
|---|---|---|
| `node` `^22.19.0 \|\| >=24.0.0` | repository `engines` | compatible |
| `pnpm@11.7.0` | repository `packageManager` | compatible |
| `git` | repository | compatible |
| PowerShell 5.1+ | `dsh-web.ps1`, `install-dsh-web-shortcut.ps1` (branch) | compatible |
| `magick` (ImageMagick) | `install-dsh-web-shortcut.ps1` icon rendering (branch) | actionable, optional |
| `apps/web/public/favicon.svg` | deleted by this branch | named by no profile, settings file, or root script |
| `apps/desktop/resources/icon.svg`, `icon-windows.svg`, `icon-macos.svg` | deleted by this branch | named by no profile or settings file; the installer reads the `.png` and `.ico` exports |
| `DEEPSEEK_API_KEY` | real-API tests and demos, read from the repository root `.env` | required only for e2e; unit tests and the build do not read it |
| the plugin checkout behind the profiles' `link:` targets | the DSH web and desktop profiles (profile) | required by the profiles |

Resolutions:

- `DEEPSEEK_API_KEY` lives in the repository root `.env`, which is gitignored and per-machine. Recreate that file on a new machine; never commit the value.
- The DSH profiles link plugin directories by absolute path. Those links survive a pull and keep pointing at the old checkout, so a machine that moved the checkout rewrites them.
- ImageMagick is needed only for the shortcut icon. Without it, `install-dsh-web-shortcut.ps1` warns and installs the shortcut with the default console icon; `-ForceIcon` re-renders once it is installed.

## Steps on another machine

1. `git pull` the branch.
2. `pnpm install` — the branch changes no lockfile entry of its own, but the base moves `pnpm-lock.yaml`, so the checkout has to match the lockfile the base carries.
3. Install the toolchain: Node `^22.19 || >=24`, `pnpm@11.7.0`, and PowerShell 5.1+.
4. Install ImageMagick, or accept the default console icon for the Start Menu shortcut.
5. Recreate the repository root `.env` holding `DEEPSEEK_API_KEY` when real-API tests or demos are needed.
6. Clone the plugin repository the DSH profiles link to and repoint their `link:` targets at it. The profiles are per-machine and cannot be pulled.
7. Install the shortcut: `pwsh -File install-dsh-web-shortcut.ps1`; pass `-ForceIcon` to re-render the icon. A machine that already holds the `DSH Web` Start Menu shortcut and its icon keeps both; the rebase does not move either target.
8. Run the verification commands below.
