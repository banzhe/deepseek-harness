### feat(skills): 新增 rebase 到 master 的本地需求笔记工作流

Adds the local-requirement-note workflow: a trailing `## Local requirement notes` rule in root `AGENTS.md`, the `dsh-rebase-onto-master` skill that writes one note per local requirement or fix under `.agents/skills/dsh-rebase-onto-master/notes/`, the note and migration READMEs, and the migration document for this base. Paths: `.agents/skills/dsh-rebase-onto-master/`, `AGENTS.md`. Machine-facing: none.

### fix(open-in-app): Windows 定位器改用 --new-window 并过滤继承的 Electron Node 模式

On Windows, `packages/host/open-in-app` passes `--new-window` from the VS Code locators, so opening a second workspace focuses a window already holding that exact directory instead of loading the new directory into the last active window and evicting the project it held. The behaviour no longer depends on the deployment-invisible `window.openFoldersInNewWindow` setting.

`launchDetachedApp` also drops the inherited `ELECTRON_RUN_AS_NODE` before merging the adapter's explicit `launch.env`. The Desktop Host runs the shared Web application through the same Electron executable in Node mode, and `scrubbedParentEnv()` preserved that selector, so every GUI application the header button launched started as Node, rejected its own argv, exited nonzero inside the launch watch window, and was reported as a failed launch. An adapter that deliberately needs Node mode — GitHub Desktop's packaged CLI — still declares it and receives it.

Paths: `packages/host/open-in-app/src/catalog.ts`, `src/resolver.ts`, `tests/resolver.spec.ts`. Machine-facing: none.

### fix(fs-local): 重试 ReplaceFileW 瞬时共享锁与 1175 删除冲突

`packages/fs/fs-local` retries `ReplaceFileW` on Win32 errors 32, 33, and 1175 after 25, 50, and 100 ms, maps exhaustion to `EBUSY`, lets the write abort signal cancel a retry wait, and keeps publication on `ReplaceFileW` instead of falling back to rename.

Paths: `packages/fs/fs-local/src/win32.ts`, `src/fsio.ts`, `tests/win32.spec.ts`, `tests/fsio.spec.ts`. Machine-facing: none.

### feat(web): 图标改为圆角光栅图标集并拆分 maskable 用途

The browser tab and installed application switch from `favicon.svg` to a raster set. `favicon.ico`, `icon-192.png`, and `icon-512.png` are rounded with alpha; `icon-maskable-192.png`, `icon-maskable-512.png`, and `apple-touch-icon.png` stay opaque so the platform mask does not cut a second shape. The manifest declares real pixel sizes and splits `purpose` into `any` and `maskable`. `packages/host/frontend-static` gains `.png` and `.ico` MIME entries without which the icons serve as `application/octet-stream`, and the desktop bundle allowlist in `apps/desktop/src/main.ts` follows the raster paths so the packaged app does not 404 its own icons.

Paths: `apps/web/public/*`, `apps/web/index.html`, `apps/web/tests/pwa-manifest.e2e.ts`, `apps/web/tests/clickable-links-gallery.e2e.ts`, `apps/web/tests/settings-chrome.e2e.ts`, `apps/desktop/src/main.ts`, `packages/host/frontend-static/src/index.ts`, `packages/host/frontend-static/tests/frontend-static.spec.ts`. Machine-facing: every `apps/web/public` file is served from a fixed URL.

### chore(scripts): 新增 DSH Web 启动脚本与开始菜单快捷方式安装脚本

Adds `dsh-web.ps1` (runs `pnpm dsh web --no-open` from the repository root and propagates pnpm's exit code) and `install-dsh-web-shortcut.ps1` (creates the `DSH Web` Start Menu shortcut, renders a multi-size icon with ImageMagick from `website/public/favicon.svg`, and refreshes an existing taskbar pin).

Machine-facing: both scripts are new and live at the repository root. `dsh-web.ps1` requires `pnpm` and `pwsh` on `PATH`; the installer also looks for `magick`, which is optional.

### feat(ui-workspace): 折叠的工作区分组图标增加执行中与已完成未读提示

The sidebar session tree's Workspace (folder) header reports both hidden row states while the group is folded. A folded group shows no session rows, so their status dots are off screen; the header's closed-folder glyph carries the same animated `ongoing` state dot as a badge, labelled `group.running` (`有会话正在运行` / `A session is running`), and the `done` reminder of a member that finished running while not selected and not yet viewed, labelled `group.completed` (`有会话已完成，未读` / `A session finished and is unread`). Running takes the badge seat when both are true, so the two states never stack.

`GroupNode.running` is derived in `deriveGroups` from the group's visible members, counting direct children through each Session's subagent catalog. `GroupNode.completedUnread` is derived from those members' `completionUnread` status, and subagent-origin rows are never visible members. Both are always false while the group is expanded, where each row carries its own status dot. The badges take no focus; the enclosing row keeps its single toggle action.

Paths: `packages/client/ui-workspace/src/client/tree.ts`, `rows/Rows.tsx`, `rows/Rows.module.css`, `locales.ts`, `tests/tree.client.spec.ts`, `tests/rows.client.spec.tsx`. Machine-facing: none.

### fix(desktop-host): 修复 Windows 打包版 LibreOffice 引擎路径过长

Packaged Windows LibreOffice conversion fails when the unpacked engine directory is long enough that LibreOffice's `file:///` resource URLs exceed 260 characters: the resources are addressed from the program directory, and the deepest registry resource crosses the Windows 260-character limit with `stat'ed file did not exist`.

The fix replaces module hooks, which only reached the Electron Host thread, with a short junction: the Desktop Host publishes `%LOCALAPPDATA%\dsh-libreoffice-kit\node_modules` and writes a `libreoffice-cli.mjs` entry beside it that starts the CLI with `--preserve-symlinks` and `--preserve-symlinks-main`, so a child `node.exe` — the path the Office skill tells the model to run — stays on the alias instead of `realpath`ing back to the long directory. Aliases are skipped when the engine directory already fits, and a location that is itself over the limit fails loud instead of silently falling back.

Paths: `apps/desktop-host/src/office-engine.ts`, `apps/desktop-host/src/office.ts`, `apps/desktop-host/tests/office-engine.spec.ts`. Machine-facing: the junction and its `libreoffice-cli.mjs` entry live under `%LOCALAPPDATA%` on the packaging host and are recreated per run.

### feat(desktop): 新增渲染进程唤起窗口的 IPC 通道

A notification click switches the Session, but the renderer cannot raise its own window: Chromium requires a browser-layer implementation that Electron does not expose, so the switched Session would render behind whichever application is in front. The Desktop application gains the `window.reveal()` product API, backed by the `dsh-desktop:window-reveal` channel. The preload exposes `reveal()` on `window`, and the main process handles it by calling `focusPrimaryWindow` after `assertProductSender` checks the caller's document origin, restoring, showing, and focusing the existing window. No window is created when none is open.

Paths: `apps/desktop/src/ipc.ts`, `src/main.ts`, `src/preload-app.ts`, `tests/main-startup.spec.ts`, `tests/preload-app.spec.ts`. Machine-facing: a new IPC channel name a packaged renderer invokes, and a new member of the preload-exposed product API.

### feat(desktop): 应用与托盘图标改用 Web 启动器同款圆角原稿

The Desktop application, installer, and uninstaller icons were whale/gradient artwork unrelated to the Web launcher icons, so one product showed two marks. `apps/desktop/resources/icon.png` now holds the same square artwork the Web application ships, and `pnpm run render:icons` derives every Desktop artifact from it at the Web corner radius (22% of the edge): full-bleed `icon-windows.png`, transparent-margin `icon-macos.png`, and the 16–64 px `tray-windows.ico` bitmaps. The whale vectors `icon.svg`, `icon-windows.svg`, and `icon-macos.svg` are deleted, and the `render:tray-icon` script is renamed to `render:icons`.

Paths: `apps/desktop/resources/*`, `apps/desktop/scripts/render-app-icons.ts`, `apps/desktop/scripts/render-tray-icon.ts`, `apps/desktop/tests/tray-icon.spec.ts`, `apps/desktop/package.json`. Machine-facing: the renamed script, and the icon files the installer and the tray read.

### ci(desktop): 为 my_dev 发布 unsigned Electron 并从 GitHub Release 更新

Adds the personal `my_dev` release workflow: manual dispatch and every push to `my_dev` build an unsigned installer on `windows-latest` and an unsigned arm64 DMG on `macos-latest`, then publish both into one version-tagged GitHub Release whose notes point at the latest release feed.

The Windows job runs `prepare-my-dev-windows.mjs`, which writes `apps/desktop/.env.windows` from `PACKAGE_POLICY_ORIGIN` and `PACKAGE_LOGIN_ORIGINS` and resolves the build version; the build runs with `DSH_DESKTOP_GITHUB_RELEASE_FEED=1` and `DSH_DESKTOP_GITHUB_REPOSITORY`, and the job rewrites the emitted `nightly.yml` through `githubReleaseMetadata` so installed builds update from the latest GitHub Release. The macOS job runs `prepare-my-dev-macos.mjs` for its version and uploads the DMG. Each job reuses an existing release rather than failing when the other platform published first, and the generated `apps/desktop/.env.windows` is removed in an `if: always()` step.

Paths: `.github/workflows/my-dev-electron-release.yml`, `.github/workflows/prepare-my-dev-windows.mjs`, `.github/workflows/prepare-my-dev-macos.mjs`, `apps/desktop/scripts/electron-builder-config.mjs`. Machine-facing: a new workflow, the `DSH_DESKTOP_GITHUB_RELEASE_FEED` and `DSH_DESKTOP_GITHUB_REPOSITORY` environment variables, and `apps/desktop/.env.windows` on the runner only.

### fix(desktop): 修复 Windows 系统通知点击无法激活会话

Two Windows gaps broke the app-notification plugin's click-to-session flow. The process never set an AppUserModelID, so Windows silently discarded renderer toasts. Renderer notification clicks also never fire from the Windows notification center (electron#29461), so a click on a retained toast did nothing.

The shell sets the AppUserModelID from the packaged manifest's `dshDesktopAppId`, derived from the package name in development. It exposes a `dshDesktop.notifications` preload channel (`show`, `close`, `onActivate`) backed by a main-process toast router whose Windows toastXml `launch` attribute routes `dsh://open?notification=<id>` protocol activations — including second-instance argv handoffs — back to the renderer, which maps the echoed id onto its click target and calls `openSession`. The consumer plugin (dsh-plugins `app-notification`) prefers this channel and keeps the HTML5 constructor for browsers.

Paths: `apps/desktop/src/desktop-notifications.ts`, `src/ipc.ts`, `src/main.ts`, `src/preload-app.ts`, `src/single-instance.ts`, `tests/desktop-notifications.spec.ts`, `tests/main-startup.spec.ts`, `tests/preload-app.spec.ts`, `tests/single-instance.spec.ts`, `tests/welcome-startup.spec.ts`. Machine-facing: the `dsh:open` protocol URL, the `dshDesktop.notifications` preload channel, and the AppUserModelID the packaged manifest supplies.

## Compatibility with this machine

Rows marked **branch** come from this branch. Rows marked **base** come from the release this branch lands on, and still have to hold on a machine that runs the affected command. Rows marked **profile** are state a checkout keeps outside the repository that `git pull` cannot migrate. Host paths, host versions, and local state are deliberately not recorded here; the requirements below are what another machine must satisfy.

Resolutions:

- `DEEPSEEK_API_KEY` lives in the repository root `.env`, which is gitignored and per-machine. Recreate that file on a new machine; never commit the value.
- The DSH profiles link plugin directories by absolute path. Those links survive a pull and keep pointing at the old checkout, so a machine that moved the checkout rewrites them.
- ImageMagick is needed only for the shortcut icon. Without it, `install-dsh-web-shortcut.ps1` warns and installs the shortcut with the default console icon; `-ForceIcon` re-renders once it is installed.
- `package:desktop:mac:arm64:unsigned` runs only on macOS, where `/usr/bin/codesign` ships with the OS. The base's command reads no `.env.macos` and no release credentials, and needs no Developer ID, p12, keychain entry, or notarization setting. An unsigned arm64 build requires Apple silicon, and a local x64 command exists as well.
- The `my_dev` release workflow publishes to the repository the branch lives in. It needs no secret beyond the token GitHub provides, and the placeholder `policy_origin` default is sufficient for a personal unsigned build.

## Steps on another machine

1. `git pull` the branch. The consolidation rewrote history, so a checkout that carried the previous sixteen commits needs `git fetch origin my_dev` and a reset onto the rewritten tip rather than a fast-forward.
2. `pnpm install` — the base moves workspace manifests and `pnpm-lock.yaml`, so the checkout has to match the lockfile it carries.
3. `pnpm run clean` before the first build, when the checkout built the pre-rebase tree. The base moved `session-title-all-prompts-llm` out of `packages/session/`, and the old directory survives the pull as `lib/` and `node_modules/` with no `src/` or `package.json`; `pnpm run build` then fails at `lib/types/index.js` with `[MISSING_EXPORT] "registerSessionTitleLlmProvider" is not exported by "../session-title-llm/src/index.ts"`. The clean removes that residue.
4. Install the toolchain: Node `^22.19 || >=24`, `pnpm@11.28.5`, and PowerShell 5.1+.
5. Install ImageMagick, or accept the default console icon for the Start Menu shortcut.
6. Recreate the repository root `.env` holding `DEEPSEEK_API_KEY` when real-API tests or demos are needed.
7. Clone the plugin repository the DSH profiles link to and repoint their `link:` targets at it. The profiles are per-machine and cannot be pulled.
8. Install the shortcut: `pwsh -File install-dsh-web-shortcut.ps1`; pass `-ForceIcon` to re-render the icon. A machine that already holds the `DSH Web` Start Menu shortcut and its icon keeps both; the rewrite does not move either target.
9. Re-run any locally produced Desktop icons with `pnpm run render:icons`; the script was renamed from `render:tray-icon`.
10. Run the verification commands below.
