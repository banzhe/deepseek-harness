## Rebase resolutions

One commit stopped on conflicts: `feat(ui-workspace): 折叠的工作区分组图标增加执行中状态`, whose note the base does not contain. Both conflicted files belong to it:

- `packages/client/ui-workspace/src/client/tree.ts` — the base deleted `hasActiveSchedule`, a helper with no callers on either side. The local side carried it only as unchanged context above the new `groupRunning` helper. Resolution: keep the `groupRunning` helper, drop the dead `hasActiveSchedule`.
- `packages/client/ui-workspace/tests/tree.client.spec.ts` — the base added archived-filter cases at the same insertion point as the new folded-group cases. Resolution: keep both blocks.

The replay merged cleanly in `tests/rows.client.spec.tsx`, but the base had added more `GroupNode` fixture literals there, and `GroupNode` now requires the `running` and `completedUnread` fields this branch introduced. `npx tsc -b tsconfig.client.json` failed with `TS2739` on them, so `pnpm run build` failed at the typecheck step.

Both commits that own `GroupNode` were amended through an `edit` rebase so every commit's tree typechecks on its own, rather than leaving the repair in the top commit: `feat(ui-workspace): 折叠的工作区分组图标增加执行中状态` gives each fixture the `running` field it introduced, and `feat(ui-workspace): 折叠的工作区分组图标增加已完成未读提示` adds `completedUnread`.

### fix(open-in-app): VS Code 的 Windows 定位器改用 --new-window

On Windows, `packages/host/open-in-app` passes `--new-window` from the VS Code locators, so opening a second workspace focuses a window already holding that exact directory instead of loading the new directory into the last active window and evicting the project it held. The behaviour no longer depends on the deployment-invisible `window.openFoldersInNewWindow` setting.

Paths: `packages/host/open-in-app/src/catalog.ts`, `tests/resolver.spec.ts`. Machine-facing: none.

### fix(fs-local): 重试 ReplaceFileW 瞬时共享锁与 1175 删除冲突

`packages/fs/fs-local` retries `ReplaceFileW` on Win32 errors 32, 33, and 1175 after 25, 50, and 100 ms, maps exhaustion to `EBUSY`, lets the write abort signal cancel a retry wait, and keeps publication on `ReplaceFileW` instead of falling back to rename.

Paths: `packages/fs/fs-local/src/win32.ts`, `src/fsio.ts`, `tests/win32.spec.ts`, `tests/fsio.spec.ts`. Machine-facing: none.

### feat(web): 图标改为圆角光栅图标集并拆分 maskable 用途

The browser tab and installed application switch from `favicon.svg` to a raster set. `favicon.ico`, `icon-192.png`, and `icon-512.png` are rounded with alpha; `icon-maskable-192.png`, `icon-maskable-512.png`, and `apple-touch-icon.png` stay opaque so the platform mask does not cut a second shape. The manifest declares real pixel sizes and splits `purpose` into `any` and `maskable`. `packages/host/frontend-static` gains `.png` and `.ico` MIME entries without which the icons serve as `application/octet-stream`, and the desktop bundle allowlist in `apps/desktop/src/main.ts` grows from `/favicon.svg` to the raster paths so the packaged app does not 404 its own icons.

Paths: `apps/web/public/*`, `apps/web/index.html`, `apps/web/tests/pwa-manifest.e2e.ts`, `apps/web/tests/clickable-links-gallery.e2e.ts`, `apps/web/tests/settings-chrome.e2e.ts`, `apps/desktop/src/main.ts`, `packages/host/frontend-static/src/index.ts`, `packages/host/frontend-static/tests/frontend-static.spec.ts`. Machine-facing: every `apps/web/public` file is served from a fixed URL. The installer script reads its icon source from `website/public/favicon.svg`, which this branch keeps.

### feat(ui-workspace): 折叠的工作区分组图标增加执行中状态

The sidebar session tree's Workspace (folder) header reports executing work while the group is folded. A folded group shows no session rows, so their status dots are off screen; the header's closed-folder glyph carries the same animated state dot as a badge, labelled `group.running` (`有会话正在运行` / `A session is running`). `GroupNode.running` is derived in `deriveGroups` from the group's visible members, counting direct children through each Session's subagent catalog, and is always false while the group is expanded. The badge takes no focus; the enclosing row keeps its single toggle action.

Paths: `packages/client/ui-workspace/src/client/tree.ts`, `rows/Rows.tsx`, `rows/Rows.module.css`, `locales.ts`, `tests/tree.client.spec.ts`, `tests/rows.client.spec.tsx`. Machine-facing: none.

## Compatibility with this machine

Rows marked **branch** come from this branch. Rows marked **profile** are state a checkout keeps outside the repository that `git pull` cannot migrate. Host paths, host versions, and local state are deliberately not recorded here; the requirements below are what another machine must satisfy.

| Item | Required by | Result |
|---|---|---|
| `node` `^22.19.0 \|\| >=24.0.0` | repository `engines` | compatible |
| `pnpm@11.7.0` | repository `packageManager` | compatible |
| `git` | repository | compatible |
| PowerShell 5.1+ | `dsh-web.ps1`, `install-dsh-web-shortcut.ps1` (branch) | compatible |
| `magick` (ImageMagick) | `install-dsh-web-shortcut.ps1` icon rendering (branch) | compatible, optional |
| `bun` | DSH web profile MCP row (profile) | compatible, on `PATH` |
| `COMMANDCODE_API_KEY` | MCP server checkout, read from its own `.env` (profile) | compatible |
| `CLIPROXYAPI_API_KEY` | DSH web profile `llm-pi-ai` provider (profile) | compatible |
| `apps/web/public/favicon.svg` | deleted by this branch | named by no profile, settings, or root script |
| `website/public/favicon.svg` | `install-dsh-web-shortcut.ps1` icon source | required by the installer |
| the `dsh-plugins` checkout | six `link:` targets in the DSH web profile (profile) | required by the profile |

Resolutions:

- `CLIPROXYAPI_API_KEY` backs the profile's only model provider. It lives in the DSH home's credentials file (`~/.dsh/.credentials.yaml`), which is per-machine; supply it there on a new machine. The repository root needs no `.env` for it.
- `COMMANDCODE_API_KEY` is read by the MCP server from its own checkout, not from this repository: the profile row sets that checkout as the MCP `cwd`, and `bun` loads `.env` from there. Recreate that `.env` on a new machine.

## Steps on another machine

1. `git pull` the branch.
2. `pnpm install` — no local commit changes `pnpm-lock.yaml`, so the checkout only has to match the lockfile the base already carries.
3. Install the toolchain: Node `^22.19 || >=24`, `pnpm@11.7.0`, PowerShell 5.1+, and `bun` for the profile's MCP row.
4. Install ImageMagick, or accept the default console icon.
5. Create the MCP server checkout's `.env` holding `COMMANDCODE_API_KEY`, and add `CLIPROXYAPI_API_KEY` to the DSH home's credentials file.
6. Clone the `dsh-plugins` repository — the DSH web profile links six of its plugin directories by absolute path.
7. Recreate the DSH web profile. It is per-machine and cannot be pulled: its `package.json` links local checkouts by absolute path, and `cordis.patch.yml` names the `bun` MCP row by absolute path. Rewrite those paths for the new machine, or rebuild the profile from `packages/bundle/web-app`.
8. Install the shortcut: `pwsh -File install-dsh-web-shortcut.ps1`; pass `-ForceIcon` to re-render the icon. A machine that already holds the `DSH Web` Start Menu shortcut and its icon keeps both; the rebase does not move either target.
9. Run the verification commands below.
