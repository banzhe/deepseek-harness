# 本地添加功能或修复

本 skill 只规定流程。这里的“上游”指 DSH 官方仓库（`origin/master` 所代表的官方发布线），不是指本地分支。所有需求和修复默认不向 DSH 官方上游提交，即不推送到官方、不提 PR。所有改动都在 `my_dev` 分支中进行；本仓库的提交仅供个人使用。

## 1. 确认范围

1. 确认当前分支为 `my_dev`（`git branch --show-current`）。不是时，停止并询问，不要在其他分支上改动。
2. 确认是需求还是修复，并确认改动不会提交给 DSH 官方上游。
3. 只改完成需求所必需的内容。改动越少越好。
4. 任一点不清楚时先询问，不要猜。

## 2. 写本地 note

每个本地需求或修复都必须在同一改动中写一条 note，位置为 `.agents/skills/dsh-rebase-onto-master/notes/`。

1. 按 `notes/README.md` 的模板创建 `YYYY-MM-DD-<kebab-topic>.md`。
2. 写明 `Kind`（requirement 或 fix）、`Status: local`、涉及路径、唯一字符串或测试名，以及 **Already-on-master 测试**。
3. 没有 note 的本地 commit，之后变基时会被标记为不确定并阻塞变基。

## 3. 实现

- 最小化改动，只改实现需求所必需的文件。
- 不要为了承载本地需求而修改上游 README、Agent Notes、配对 sidecar、文档门禁或无关文档。
- 不要顺手重构、清理或改动无关代码。

## 4. 验证

只运行能证明本次改动的最少检查：

1. 与改动直接相关的测试。
2. 改动涉及的类型检查或构建，若有必要。

不要默认运行全量测试。需要更多检查时，再由用户决定。

## 5. 提交

本仓库的提交仅供个人使用，不用于 DSH 官方上游。只有用户明确要求时才 `git commit`，提交到 `my_dev`。否则保持改动未提交。

## 6. 报告

- 改动的文件与新增的 note 路径。
- 运行过的验证命令与结果。
- 未验证的部分，以及原因。
